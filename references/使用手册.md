# 使用手册（中文·一页纸）

面向"只想把视频做出来"的日常使用。技术细节见
`references/安装与前置条件.md` 与 `references/工作流接入说明.md`。

> **找不到入口时看** `references/入口指引-三条路线怎么选.md`（两条路线怎么选、第一个动作是什么、
> 每步命令、怎么确认走对了）。导演系统忘了下一步，敲：
> `.venv\Scripts\python.exe director_system\scripts\next_step.py`

## 先选路线（三条）

| 路线 | 适合 | 有什么不同 | 看哪一节 |
| --- | --- | --- | --- |
| **A. 导演系统**（原创短片） | 你要的是"一部有创意、有审核的短片" | 创意 → 剧本 → 分镜都过一遍**独立评审**，中间停 **3 道人工程序闸门**；提示词按分镜逐镜结构化编译；质量明显更高 | **第十节** |
| **B. 快速线**（已有讲稿直接出片） | 你手里已经有讲稿，只想把它变成视频 | 讲稿 → 分段 → 出片 → 合成，一步到底，没有人工闸门 | 第一节 |
| **C. 快速出片**（轻量导演通道，触发词「快速出片」「无审核」） | 你只给一个主题，但想要**剧本/分镜/逐镜六段式提示词**，不想走三道闸门 | 一条命令出剧本+分镜+提示词+渲染计划，**无评审、无闸门、零确认**（同快速线）；返修有上限；产物带 `_fast` 后缀，与 A 互不覆盖 | **第十节之二** |

三条路线共用同一套执行层（ComfyUI 出图/出片 + FFmpeg 合成）与同一套硬性约束，见第十一节。

## 一、做一条视频（推荐方式，四步）

1. **先启动 ComfyUI**（用你平时的启动器），确认它开着。
2. **写讲稿**：复制 `data\briefs\示例讲稿.txt`，把内容改成你的故事，另存成新文件，
   例如 `data\briefs\我的故事.txt`。
3. **双击项目根目录的 `开始制作.cmd`**，按提示回答四件事（脚本用 `[1/4]`～`[4/4]` 标出，
   提示语是英文，含义如下）：
   * `[1/4] Project name`：项目名，英文或拼音，例如 `my-film-01`（不要用中文和空格）；
   * `[2/4] Brief file`：讲稿文件；它会先列出 `data\briefs\` 里可用的 txt，
     填文件名（例如 `示例讲稿.txt`）或完整路径都行；
   * `[3/4] Target length in minutes`：成片时长（分钟），直接回车＝2 分钟；
   * `[4/4] Style profile`：风格档位，直接回车＝`guofeng-cg`（国风 3D 动漫）。
     做**现代/科幻/写实**题材时填 `photoreal-cinematic`（电影质感实拍写实）。
     两个档位的具体文字在 `config\styles.yaml`，可以自己加新档位。
4. 它会先打印一份**计划**给你看，回车确认后开始跑（输入 `n` 则取消）。跑完会告诉你成片在哪。

> 想重复跑或让脚本自动跑，也可以直接带参数调用：
> `开始制作.cmd <项目名> <讲稿文件> [分钟数] [plan|yes] [风格档位]`
> —— `plan` 表示只打印计划、`yes` 表示不再询问直接开跑。

> 如果你是在对话里**只给 Codex 一句话主题**（不说"导演系统"），它会走同一套快速线，但**全程不会问你任何事**：
> 自己拉起 ComfyUI、自己写完剧本与提示词、出图出片、合成、体检、交付前核对，跑完关掉自己拉起的 ComfyUI，
> 最后把成片与质检结论一并发给你。只有"主题/参数缺失"或"发现画面硬伤需要你定夺"时才会来找你。

**产物位置**：

| 想要什么 | 在哪 |
| --- | --- |
| 成片 | `projects\<项目名>\final\<项目名>.mp4` |
| 制作报告（耗时/分段/字幕体检结论） | `projects\<项目名>\report.md` |
| 剧本 | `projects\<项目名>\script.md` |
| 每段提示词 | `projects\<项目名>\prompts\seg-0N.txt`（可以手改，改完重跑即生效） |
| 分段视频 | `projects\<项目名>\segments\` |

> 每个提示词里都自动带一行 **【人物锁定】**（写明本段只出现哪几名角色、各自穿什么、
> 颜色不许改）。这是 2026-10-13 加上的：只写"两人"会让模型把主角画成路人、把衣服换色。
> 手改提示词时**别删这一行**；自己写镜头文字时，也照它的格式逐镜点名角色并带上服装颜色。

**要等多久**（2026-10-13 实测，2 分钟成片全程 68 分钟）：

* 剧本（DeepSeek）：约 1 分钟；
* 参考图（角色三视图 + 分镜图，10 张）：约 3.5 分钟（每张 20 秒）；
* 分段出片：每 15 秒的段落约 **8 分钟** —— 2 分钟成片 8 段共约 64 分钟；
* 合成 + 体检 + 报告：约 1 分钟。

所以 **2 分钟成片 ≈ 70 分钟**，5 分钟成片 ≈ 3 小时。

## 二、跑了一半断了／电脑重启了怎么办

**什么都不用修，把同样的命令（或双击）再执行一次就行**：
已经做完的步骤会自动跳过，没做完的接着做，不会重复消耗显卡。

## 四、只做其中一段／重做某一段

```powershell
# 重做某一段：自动备份台账 + 把旧产物归档到 segments\_superseded\，然后按提示重跑
.venv\Scripts\python.exe scripts\run_batch.py regen --project <项目名> --id seg-04 ^
    --reason "字幕重做" --seed 20261231

# 先演练（不改任何东西）
.venv\Scripts\python.exe scripts\run_batch.py regen --project <项目名> --id seg-04 --plan
```

## 五、体检与报告

```powershell
# 字幕体检（画面里有没有被烧进去的字幕；只报告，不改画面）
.venv\Scripts\python.exe scripts\check_segment_text.py --project <项目名> --write-report

# 出一份中文制作报告
.venv\Scripts\python.exe scripts\project_report.py --project <项目名>
```

**要做有台词/旁白的片子**（2026-10-15 定案；声音策略在 `brief.json` 的 `voice_policy`，缺省＝对白 `h3`、旁白 `tts`）：

* **对白：默认让视频模型直接说**——台词写成固定格式的**对白行**进时间轴
  （`角色名（神态，声音特征）说：“台词”`，每句 ≤20 字），同段写明"只有这句是人声、不要字幕"。
  中文准确、口型天然同步；**代价是模型常把台词同时画成画面字幕**（负面词在这个工作流里不生效）。
  因此**每段出片后跑一次字幕体检**：
  `.venv\Scripts\python.exe scripts\check_segment_text.py --project <片名> --write-report`；
  **按用户 2026-10-15 的口径：只检出、只报告，不主动返修**——交付报告里给出
  「哪几段有字幕、各在哪一秒、占全片多少」，用户觉得需要返修时再动手
  （`run_batch.py regen --project <片名> --id <段> --reason “字幕” --seed <新种子>`、定点修复、或把那句改成画外人声）。
* **旁白：默认走 TTS**——`director_system\scripts\make_narration.py --film-id <片名>` →
  `run_batch.py create/run --project <片名>-narration` →
  `mix_narration.py --project <片名> --narration <片名>-narration --input 成片 --output 带配音成片`。
  也可以把旁白写成画外人声台词让模型念（实测那条画面是干净的）。
* **不要再用"音频参考驱动口型"**：2026-10-15 实测无效（模型念出的是听不懂的语言、嘴也不动）。
* 台词条目一律写进提示词包/剧本的 `dialogue`（说话人/文本/是否旁白/音色），配音与核对都靠它。

**关于字幕**：模型有时会把台词烧成画面文字，换种子、改提示词写法都试过，**去不掉**，
属于已知现象。当前策略是**接受**。确实需要无字幕版时，按
`references/实测经验与坑.md` 第七节做定点像素修复（效果一般，是备用方案）。

## 六、出问题怎么查（常见现象对照）

| 现象 | 多半原因 | 怎么办 |
| --- | --- | --- |
| 提示 ComfyUI 连不上 | ComfyUI 没启动，或跑完自己退出了 | 用启动器重新打开，再执行一次同样的命令 |
| 提示"队列非空闲" | 有别的任务在跑 | 等它跑完；或去 ComfyUI 界面看队列 |
| DeepSeek 报 401 / 超时 | 密钥或网络问题 | 检查 `.env` 里的 `DEEPSEEK_API_KEY`；网络是否可用 |
| 某段连续失败 3 次 | 显存不足、模型被占用 | 看 `data\logs\batch-*.log` 最后几行；关掉占显存的程序后重跑 |
| "成片已存在，未覆盖" | 保护机制 | 想覆盖加 `--force-compose`，或先改名/移动旧成片 |
| 提示"Git 有未提交改动" | 正常提醒 | 确认无误后 `git add -A` 与 `git commit` |
| 画面里有字幕 | 模型行为（已知） | 接受；或用备用修复方案（见第五节） |

**一条原则**：报错信息最后一句永远是"下一步该怎么做"，照着做即可。

## 七、换风格（现代/科幻/写实题材）

风格文字全部集中在 `config\styles.yaml`，代码里不写死。现有两个档位：

| 档位名 | 适合什么题材 |
| --- | --- |
| `guofeng-cg`（默认） | 玄幻、武侠、古风（3D 国漫 CG 观感） |
| `photoreal-cinematic` | 现代、科幻、灾难、实拍写实（电影质感） |

* 双击流程：在第 4 问填档位名；命令行：加 `--style photoreal-cinematic`。
* 档位名写错时脚本会直接列出可选值，不会跑到一半才报错。
* 要加新档位：复制 `config\styles.yaml` 里的一段改文字即可（风格行 / 背景音乐要求 /
  负面词 / 给 DeepSeek 的风格要求 / 参考图风格后缀），改完先用 `--plan` 看一遍。

## 八、三条红线（别做）

1. **不要动 ComfyUI 里的任何东西**：不重装/升级 ComfyUI、H3 模型、PyTorch、CUDA、
   custom_nodes；不往它的解释器里装包。项目只通过 API 使用它。
2. **不要把密钥贴到聊天、截图、报告里**：密钥只放在 `.env`。
3. **不要手工删 `segments.json`**（那是进度台账）。要重做某段就用第四节的 `regen`，
   它会先备份台账、再把旧产物移进 `_superseded\`（只移动，不删除）。

## 十、导演系统：做原创短片（推荐）

### 10.1 一句话流程

```
创作简报 ─▶ 5个故事概念+独立评审 ─【闸门A 选案】─▶ 大纲/剧本+评审 ─▶ 分镜+评审 ─▶ 提示词包+评审
                                                              ─【闸门B 制作前确认】─▶ 出参考图 ─▶ 逐段出片 ─▶ 合成
                                                                                            ─【闸门C 成片质检】─▶ 成片
```

只有三道人工闸门（原来是四道，2026-10-14 合并）：**A 选案 / B 制作前确认 / C 成片质检**。
闸门是**真实的停机点**：状态记在 `projects\<片名>\state.json`，脚本发现上游关卡没批准会直接拒绝运行。

### 10.2 一条命令一步，每步做完停下来等你批

```powershell
$P = "my-short-01"     # 片名：英文或拼音，不要中文与空格

# 0) 先写创作简报（题材/片长/风格/受众/情绪/限制），存成 projects\$P\brief.json

# 1) 创意：5 个故事概念 + 独立评审
.venv\Scripts\python.exe director_system\scripts\make_ideas.py --film-id $P --brief-file projects\$P\brief.json
.venv\Scripts\python.exe director_system\scripts\review_gate.py --film-id $P --show      # 看闸门
.venv\Scripts\python.exe director_system\scripts\review_gate.py --film-id $P --approve A --note "选 c2，理由…"

# 2) 大纲 + 剧本 + 剧本评审（返修加 --revise）
.venv\Scripts\python.exe director_system\scripts\make_story.py --film-id $P --concept c2

# 3) 分镜 + 分镜分镜验证 + 评审（返修加 --revise）
.venv\Scripts\python.exe director_system\scripts\make_storyboard.py --film-id $P

# 4) 提示词编译（这一步做完会自动把闸门 B 置为"等你确认"）
.venv\Scripts\python.exe director_system\scripts\make_prompts.py --film-id $P --style photoreal-cinematic
.venv\Scripts\python.exe director_system\scripts\review_gate.py --film-id $P --approve B --note "同意进入批量渲染"

# 5) 出参考图：先按 prompt_pack.json 的 assets 建两个批次，再跑
#    （素材批 = 文生图；派生批 = 从已有资产派生，必须排在素材批之后）
.venv\Scripts\python.exe scripts\run_batch.py create --project $P-materials --from-json projects\$P\materials_definition.json
.venv\Scripts\python.exe scripts\run_batch.py create --project $P-derive    --from-json projects\$P\derive_definition.json
.venv\Scripts\python.exe scripts\sync_inputs.py --project $P          # 参考图必须先同步进 ComfyUI 的 input
.venv\Scripts\python.exe scripts\run_batch.py run --project $P-materials
.venv\Scripts\python.exe scripts\sync_inputs.py --project $P-derive
.venv\Scripts\python.exe scripts\run_batch.py run --project $P-derive

# 6) 出片（render_plan.json 是阶段 6 的渲染计划；先 dry-run 看要跑几个任务）
.venv\Scripts\python.exe scripts\run_batch.py dry-run --project $P
.venv\Scripts\python.exe scripts\run_batch.py run --project $P

# 7) 合成 + 质检
.venv\Scripts\python.exe scripts\compose_final.py --project $P
.venv\Scripts\python.exe scripts\review_gate.py --film-id $P --approve C --note "成片验收通过"
```

**阶段复用（2026-10-15 起，省调用）**：四个阶段都自己判断"这一段做完没有"——
产物**通过机械校验就复用、只补缺的那一段**。例如剧本已通过、只有评审那次失败：
再跑一次 `make_prompts.py` 只重做评审，不会重写剧本（会打印 `复用已有 screenplay.json`）。
要整段重做加 `--force`（旧文件先归档进 `history/`，不删）。
另外**每次请求的格式规则里现在带"结构自查"**（括号成对闭合、结尾别多写 `}`、字符串用中文引号），
专治"回复不是合法 JSON"这种一次吃掉整轮调用的毛病。

### 10.3 产物在哪

| 想要什么 | 在哪 |
| --- | --- |
| 成片 | `projects\<片名>\final\<片名>.mp4` |
| 每镜最终提示词 | `projects\<片名>\prompts\s1.txt`…（**由程序从结构化行拼出来，不要手改**；要改就改 `prompt_pack.json` 再重跑） |
| 提示词包（含出图提示词） | `projects\<片名>\prompt_pack.json` / `.md` |
| 分镜表（含空间平面图、参考图槽位） | `projects\<片名>\storyboard.json` / `.md` |
| 剧本与评审 | `projects\<片名>\screenplay.md`、`*_review.md` |
| 闸门状态与批准留痕 | `projects\<片名>\state.json` |
| 逐镜质检报告 | `projects\<片名>\analysis\shot_qc.md` 等 |
| 历史版本（从不覆盖） | `projects\<片名>\history\` |

### 10.3.5 交付前必做：核对"成片里每一段是不是台账里那一段"

```powershell
.venv\Scripts\python.exe scripts\verify_final_segments.py --project <片名>
```

它把成片按台账切成 N 个窗口，和 N 个候选源逐一降采样比对（每秒 2 帧、16×9 灰度缩略图，逐字节算差），
**全部窗口都对上自己的那一段才算通过**（退出码 0）。

为什么必须做：2026-10-15 实测——合成时临时文件名按"原文件名"命名，而"沿用上一部片的片段"与本片片段
**可能同名**（两边都有 `s2_00001-audio.mp4`），后者覆盖前者，成片开头的第 2、3 个镜头被本片同号段顶掉。
**台账与合成记录里的路径全都写得对**，所以只能靠比对画面发现（这一部是用户看片抓到的）。
同一天也用它验证了修复：修复后 12 个窗口差值全部 0.00。

### 10.3.6 评审什么时候可以放行（收敛判据）

独立评审是"每次都能再挑出几条"的机制——本片剧本返修了 5 轮，每轮仍能新找出 4~8 条（8→5→4→5）。
所以判据写在 `director_system/config/director.yaml` 的 `review_convergence` 里：

* **致命 = 0 且 严重 ≤ 2** → 可以直接放行，残余必修项随产物带进下一阶段、逐条写进闸门备注；
* 否则再修一轮，**最多 `max_revision_rounds` 轮**（默认 2），到顶就交人决定。

每个返修轮结束时脚本会打印结论（形如「评审结论：致命 1 / 严重 4 / 轻微 4，必修项 5 条 → 已达返修轮次上限（2 轮）：不再自动返修，把残余项交人决定。」）。

**必修项口径（2026-10-15 起，用户定，程序强制）**：`must_fix_before_next_stage` **只收致命与严重**——
轻微项写进 `issues` 存档即可，**不阻塞下一阶段**，也不许在下一轮重新列成必修项。
程序兜底：`make_ideas.must_fix_scope_problems()` 要求"必修项条数 ≤ 致命 + 严重 的条数"，
超了就让评审带反馈做一轮有限返修（评审提示词 `prompts/06_quality_review.md` 与
`artifact_review.schema.json` 里都写明了这条口径）。

为什么加：以前模型可以每轮往必修项里塞 4~8 条（含轻微），于是"返修 5 轮仍每轮新增"，
每轮都是"生成 + 评审"两次调用——这是路线 A 拖时间的主因。收紧之后，**轻微项不再拦路**，
`--revise` 在"没有必修项"时会直接停下并提示可以人工批准。
**批准永远是人来做**：生成脚本只能把闸门置为"等人审"。

### 10.4 分段与节奏：先叙事后技术（重要）

**不要**为了凑总时长把片子平均切几段。项目规则（`director_system\config\director.yaml` 的 `pacing_policy`）：

1. 先按剧本、戏剧节拍、场景变化、镜头运动定**镜头边界**；
2. 再按每个镜头的叙事任务分配**理想时长**（可以是 2.5 秒、18 秒这种任意值）；
3. **最后**才映射到工作流能生成的合法帧数（5.17~15.08 秒，帧数只能取 `17k+5`）；
4. 冲突时优先调整节奏、镜头边界或生成策略，**不许平均分段**；
5. 只有故事确实需要均匀节奏时才等长——三段及以上等长必须写出理由，写不出校验会报警。

映射规则：理想值落在合法区间就取**不小于**它的最近合法帧数（宁长勿短）；超过上限先改镜头设计
（拆成两个有真实剪辑点的镜头）；不足下限就合并／补拍／生成后取用。

### 10.5 同一件事只写一次（减少返修）

提示词里的**参考图声明行**与**人物锁定行**由程序生成，不是模型写的：

* 声明行按分镜的参考图槽位与资产表逐张拼——"多声明一张""编号跳号"不可能发生；
* 锁定行的角色外观/服装**只在剧本角色表里写一次**（`screenplay.json` 的 `continuity_bible.characters`），
  每个镜头只填"画面里有谁"（`storyboard.json` 的 `characters_in_frame`），锁定行自动生成；
* 校验会检查"画面描述里点名的角色有没有登记进 `characters_in_frame`"——**漏一个人就会报警**。

## 十之二、快速出片：一条命令出剧本/分镜/提示词（无闸门）

**什么时候用**：只给一个主题，但要拿到"能直接出片的剧本 + 分镜 + 逐镜六段式提示词 + 渲染计划"，
又**不想**走第十节的三道闸门。它不产生独立评审、不设闸门；产物全部带 `_fast` 后缀，
与第十节的同名产物互不覆盖。完整命令表见 `references/入口指引-三条路线怎么选.md` 第 3 节。
**零确认**：跟第一节的快速线一样，Codex 会一路跑到成片，中途不会停下来等你批（开工时说的
"预计几张图、多少分钟"只是告知）。

```powershell
$P = "my-fast-01"

# 0) 创作简报：projects\$P\brief.json（最少 from_user：theme / duration_seconds / genre / style_profile）

# 1) 一条命令出四份产物（三段 DeepSeek 调用，不出图）；先自检就加 --dry-run（不调模型、不写盘）
.venv\Scripts\python.exe director_system\scripts\make_film_fast.py --film-id $P --brief-file projects\$P\brief.json --style photoreal-cinematic

# 2) 出参考图（**素材批先跑**，多图参考批要读素材批的产物）
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\materials_definition_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P-fast-materials
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\boards_definition_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P-fast-boards

# 3) 出片 → 合成 → 交付前核对 → 关掉自己拉起的 ComfyUI
#    run 每段提交前会自动把参考图补进 ComfyUI 的 input（要关掉加 --no-auto-sync）
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\render_plan_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P
.venv\Scripts\python.exe scripts\compose_final.py --project $P --dissolve 0 --fade 0.25
.venv\Scripts\python.exe scripts\verify_final_segments.py --project $P
.venv\Scripts\python.exe scripts\stop_comfyui.py
```

| 产物 | 在哪 |
| --- | --- |
| 剧本 / 分镜 | `projects\<片名>\screenplay_fast.json / storyboard_fast.json` |
| 提示词包 + 逐镜提示词 | `prompt_pack_fast.json`、`prompts_fast\sN.txt` |
| 渲染计划 | `render_plan_fast.json`（`run_batch.py create --from-json` 直接吃） |
| 出图批次定义 | `materials_definition_fast.json`（文生图）、`boards_definition_fast.json` / `derive_definition_fast.json`（派生/多图参考） |
| 运行记录（**不含闸门**） | `state_fast.json` |
| 历史版本（从不覆盖） | `projects\<片名>\history\`（`--force` 重写时旧文件进这里） |

三条使用要点：**① `--repairs` 默认 2**（每段最多 3 次调用，超了报错停下）；
**② 断点续跑**——已写完且通过机械校验的那段不重跑，要重写加 `--force`；
**③ 质量口径不变**——三段产出的机械校验用的仍是**完整 schema**（提示词里只放"字段骨架"，
省掉近九成的说明文字，实测能把模型的结构错误压下来）。

两条省心机制（2026-10-15 起，三条路线共用）：**出片时每段提交前自动补参考图**进 ComfyUI 的
`input`（批内"后一张要用同批刚出的图"不再需要手工 `sync_inputs`，缺图会提前报出名字）；
**资产不许白出图**——提示词包里没有镜头用到、也没被别的资产派生引用的资产会被拦下。

## 十一、硬性约束（三条路线共用，实测得来）

| 约束 | 说明 |
| --- | --- |
| 一次生成＝一段连续镜头 | 段内不能换空间、不能切镜；"镜头"与"生成段"一一对应 |
| 合法时长 | 24fps、帧数只能取 `17k+5`（124~362 帧 ≈ 5.17~15.08 秒）；成片时长＝各段之和，不为了凑整秒裁切 |
| 分辨率 | 固定 1280×736（工作流登记表里 `megapixels=0.9`；**直接在 ComfyUI 界面跑这份工作流是 1376×768**，不一样） |
| 每镜参考图 ≤9 张 | 槽位顺序＝提交顺序＝提示词里的 `@图片N`；参考图必须先 `sync_inputs.py` 同步进 ComfyUI 的 `input` |
| 画面内不许有文字 | 台词写进画面提示词会被烧成画面字幕、且工作流的负面词不生效。**对白默认由视频模型直接说**（写进提示词、出片后必须抽帧核验字幕）；**旁白默认走 TTS 后期配音**；声音策略写在 `brief.json` 的 `voice_policy` |
| 同屏清晰动物头 ≤2 个 | 其余后脑勺、虚焦或剪影 |
| ComfyUI 只关自己拉起的 | 长任务跑完用 `scripts\stop_comfyui.py`（它只关本脚本拉起的那个，你自己的窗口不动） |
| 图/视频取证要降采样 | 先用 FFmpeg 生成宽 ≤768px、单张 ≤200KB 的拼图再读；**一个对话读图 ≤10 张**，结论立刻写进 md |
| 密钥 | 只在 `.env`；报告、日志、聊天里一律掩码 |
