# 把工作流接到本项目上

本项目不假设任何特定工作流，它靠一张**登记表**（`config/workflow_targets.yaml`）
知道"哪个节点、哪个输入"对应什么业务含义。换工作流 = 改这张表 + 重新核对节点 id。

> 随包已经带了两份跑主流程必需的工作流（出片 T8bridge、出图 Qwen-Image，见
> `references/安装与前置条件.md` 第 2 节）；本文是"要换成你自己的工作流"时看的。

## 1. 一次生成是怎么驱动工作流的

```text
业务参数（提示词 / 时长 / 尺寸 / 种子 / 输出前缀 / N 张参考图）
        │
        ▼
workflow_targets.yaml 的 overrides：{ 节点 id : 输入名 }
        │
        ▼
改写工作流 JSON 副本 ──HTTP──▶ ComfyUI /prompt ──▶ 队列执行
        │
        ▼
轮询 /history ──▶ 取回 output_dir 下的产物路径 ──▶ 落进台账
```

代码只认这张表，不认得具体节点是什么。所以**登记表写对，工作流就能跑**。

## 2. 登记表怎么写

```yaml
t8bridge_9ref:                     # 内部标识（project.json 里的 target 用它）
  label: 人类可读的名字
  file: workflows/<工作流文件名>.json     # 受控副本，放在项目 workflows/ 下
  archive_subdir: segments               # 产物归档到生产目录的哪个子目录
  defaults:                              # 该工作流固定要用的默认值
    clip_name: "MM-H3\\<文本编码器>.safetensors"
    megapixels: 0.9
  overrides:                             # 关键：节点 id ↔ 业务输入的映射
    prompt:           { node: 232, input: value }
    duration_seconds: { node: 132, input: value }
    seed:             { node: 235, input: seed }
    output_prefix:    { node: 180, input: filename_prefix }
    ref_image_1:      { node: 150, input: image }
    ref_image_2:      { node: 164, input: image }
    ref_image_3:      { node: 238, input: image }
    # …最多 ref_image_1..9
  notes:
    - 哪些节点是跳过状态、哪些输入语义不明而"按原值保留"（不猜）
```

规则：

* **node 是工作流 JSON 里的节点 id**，不是界面上的位置；工作流一升级就会变，必须重新核对；
* 同一个 `input` 名可以出现在多个节点上（例如分辨率分散在首帧/尾帧两个 scale 节点），
  这时把 `overrides` 的值写成**列表**，逐个改；
* 语义不明确的输入**不要猜**，保持工作流原值，并写进 `notes` 说明为什么。

## 3. 怎么核对节点 id（不要靠猜）

```powershell
# 工作流体检：列出节点、输入名、当前值，并与 ComfyUI 的 /object_info 对照
.venv\Scripts\python.exe scripts\inspect_workflow.py
```

* 工作流 JSON 里 `inputs` / `widgets_values` 的顺序，就是改写点的来源；
* `http://127.0.0.1:8188/object_info` 给出节点类型的**真实输入名**——
  两者不一致时以 object_info 为准；
* 改完工作流后**重跑一次 `inspect_workflow.py`**，再跑单段小样（见
  `references/安装与前置条件.md` 第 4 节）。

## 4. 你的工作流要满足什么

能接进来的工作流需要具备：

1. 能从 `PrimitiveStringMultiline` 之类的节点**接收一段中文提示词**；
2. 能接收**时长（秒）或帧数**、**宽高或总像素**、**随机种子**、**输出文件名前缀**；
3. 支持**多张参考图**（本项目的多参考图流水线一次最多用 9 张：若干角色设定图 + 1 张分镜图，
   第 2 段起还会自动追加一张"上一段末帧"作为连续性锚点）；
4. 产物是**带音轨的视频文件**，落在 `comfyui.output_dir` 下；
5. 走的是标准 `/prompt` + `/history` 队列接口（本地推理，不是云端付费节点）。

> 提示：ComfyUI 的节点库里有 `ComfyCloudMiniMaxH3*` 这类**云端**节点，名字很像但不是本地推理。
> 接 API 时要核对节点类型，别把云端节点当本地用。

## 5. 参考图与提示词的对应关系（最容易错的地方）

提示词第一行声明参考图角色：

```text
@图片1角色“陈默”，@图片2角色“林雨”，@图片3image“board-01.png”。
```

**`@图片N` 的序号必须与 `ref_image_1..N` 槽位的实际投放顺序一致**。
本项目按"角色设定图（按角色顺序）+ 本段分镜图"投放，第 2 段起再追加连续性锚点，
所以锚点天然落在 `ref_image_{角色数+2}` 上。接自己的工作流时，
如果槽位数量少于需要投放的图，**不要静默丢图**，应当在 `notes` 里写明并调整方案。

## 6. 工作流升级之后

1. 把新工作流导入 ComfyUI，导出/复制到项目的 `workflows/` 目录；
2. 跑 `scripts\inspect_workflow.py` 重新核对节点 id 与输入名；
3. 更新 `config/workflow_targets.yaml` 的 `overrides` 与 `notes`；
4. 跑一条**单段小样**验证，再动正式片。

已登记的工作流（T2V 4 步、FL2V 首尾帧、9 图多参考、Qwen 文生图、音乐生成）都是
同一套机制的具体例子，可以直接照抄格式。
