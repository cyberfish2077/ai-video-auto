# 安装与前置条件

目标是让一个**全新机器**从零跑出第一条片子。读完本文你应该能回答：
我这台机器够不够、缺什么、装完怎么验证。

## 1. 硬性环境

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 | 本项目在 Windows 上开发与实测；`开始制作.cmd` 依赖 Windows |
| GPU | NVIDIA，显存 **≥ 16 GB** | 实测 RTX 5060 Ti 16GB 可用；H3 的 nvfp4/int8 量化模型 + Qwen3-VL-32B 文本编码器常驻需要这个量级 |
| 内存 | ≥ 32 GB（实测 64 GB） | 出图与出片同时跑时较吃内存 |
| 磁盘 | 模型几十 GB，另留 ≥ 100 GB 给素材与分段 | 分段视频与成片体积大（2 分钟成片约 50 MB，但分段与中间产物更多） |
| Python | **3.12.x**（`>=3.12,<3.14`） | 项目自己的虚拟环境用；与 ComfyUI 的解释器互不影响 |
| FFmpeg / ffprobe | 8.x | 合成、抽帧、解码校验。任何版本 ≥ 6 通常都可以 |
| ComfyUI | 能通过 `http://127.0.0.1:8188` 访问，版本 0.3x 以上 | **项目不安装、不升级、不改动 ComfyUI**，只通过 API 调用 |

## 2. 模型与工作流

**随包带两份能跑通主流程的工作流**（都在 `workflows/`）：

| 文件 | 用途 |
| --- | --- |
| `黑科技加速双采-self-lift工作流9图_T8bridge.json` | 主力出片：多参考图（9 图槽位）生视频，带音轨 |
| `Qwen-Image-2.1-文生图.json` | 出角色三视图与每段分镜图 |

它们引用的模型（名字就是工作流里写的，放进 ComfyUI 对应目录即可）：

* **视频扩散模型**：`MM-H3\minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors`、
  `MM-H3\minimax_h3_ref2va_pruned_int8_convrot.safetensors` 等 H3 系列（int8 / nvfp4 量化版）；
* **加速 LoRA**：`MM-H3\minimax_h3_fl2v_lightx2v_turbo_4step_*.safetensors`（4 步加速）、
  `MM-H3\minimax_h3_lms_v1.0_r64_r.safetensors`、`h3_upscaler_lms_v0.1_fp32.safetensors`；
* **VAE**：`MM-H3\minimax_h3_video_vae_fp16.safetensors`、`MM-H3\minimax_h3_audio_vae_fp32.safetensors`；
* **文本编码器**：`MM-H3\qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`
  （注意：工作流原文件里写的是 `…int8_convrot` 版，本项目在
  `config/workflow_targets.yaml` 的 `defaults.clip_name` 里改成了 nvfp4_awq 版，
  换成你自己的文件名即可）；
* **出图模型**：`qwen_image_2.1_int8_convrot.safetensors`、`qwen_image_2.1_vae_bf16.safetensors`、
  `qwen3vl_8b_int8_convrot.safetensors`。

> ⚠️ **权重文件不在本仓库**（模型动辄几十 GB，且各有各的许可）。上面两份工作流来自第三方
> ComfyUI 整合包，版权属于原作者，本仓库为便于开箱使用按原样附带。
> 其余工作流（T2V、首尾帧 FL2V、音乐生成）请自备——它们的改写点已经在
> `config/workflow_targets.yaml` 里登记好了，换你自己的工作流见
> `references/工作流接入说明.md`。
>
> 附带的工作流里只做过一处清理：视频预览节点缓存的"上次打开过的文件"路径
> （`"fullpath"`）被清空——那是界面预览用的记录，与工作流执行无关，但原文件里带着
> 前一台机器的硬盘布局。除此之外逐字保留。相应的工作流登记表里，
> 指向作者本机 ComfyUI 的 `source_in_comfyui` 字段也已被删掉。

## 3. 安装步骤

```powershell
# 0) 前置：ComfyUI 已经能启动，并且 H3 模型就位

# 1) 取代码后，建立项目自己的虚拟环境（不要用系统 py，也不要用 ComfyUI 的 python_embeded）
cd <项目根>
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2) 配置
copy config\settings.example.yaml config\settings.yaml   # 改路径见下表
copy .env.example .env                                   # 填 DEEPSEEK_API_KEY

# 3) 把工作流放进 workflows\ 并登记（见 references/工作流接入说明.md）

# 4) 自检
.venv\Scripts\python.exe scripts\check_env.py
```

`check_env.py` 通过后应当输出"21 项检查，其中错误 0 项"。
任何一项报错，最后一行都会写明"下一步该怎么查/怎么修"，照着做即可。

### 必须改的配置项

| 配置项 | 含义 |
| --- | --- |
| `paths.*` | 数据、日志、缓存、生产目录、工作流目录。全部用正斜杠 |
| `comfyui.install_dir` / `comfy_dir` / `models_root` / `output_dir` / `input_dir` | 你的 ComfyUI 实际位置；`input_dir` 用来投放参考图，`output_dir` 用来取回产物 |
| `comfyui.main_workflow` | 主力工作流的受控副本（放在 `workflows/` 下） |
| `ffmpeg.ffmpeg` / `ffprobe` | FFmpeg 可执行文件路径 |
| `deepseek.model` | 用你账号实际可用的模型名 |

代码里**没有**硬编码路径；改配置就够了，不需要改代码。

## 4. 首次验收顺序（别一上来就跑 2 分钟）

按这个顺序做，出错时排查范围最小：

1. `.venv\Scripts\python.exe scripts\check_env.py` → 0 错误；
2. `.venv\Scripts\python.exe scripts\inspect_workflow.py` → 核对工作流节点与输入名；
3. **单段小样**：做一条 1 段（15 秒）的片子，跑通"出图 → 出片 → 合成 → 体检 → 报告"整条链，
   约 12 分钟；
4. 单段没问题，再做 2 分钟正式片（约 70 分钟）。

```powershell
# 单段小样（讲稿短一点即可）
.venv\Scripts\python.exe scripts\make_video.py --name smoke-01 ^
    --brief-file data\briefs\示例讲稿.txt --minutes 0.25 --style photoreal-cinematic
```

## 5. 常见安装问题

| 现象 | 原因与处理 |
| --- | --- |
| `check_env` 报"H3 模型未找到" | 模型不在 `comfyui.models_root` 下，或工作流里写的文件名与实际不一致。用 `scripts\inspect_workflow.py` 核对 |
| 报"ComfyUI 连不上" | ComfyUI 没启动，或跑完自己退了。用启动器重新打开再执行同一条命令（已完成的步骤会自动跳过） |
| 报"队列非空闲" | 有别的任务在跑。等它跑完，或去 ComfyUI 界面看队列 |
| DeepSeek 报 401 / 超时 | `.env` 里的 `DEEPSEEK_API_KEY` 没填对，或网络不可用 |
| 首次出片显存不足 | 关掉其它占显存的程序；不要为了省显存去改 ComfyUI 的启动参数——那属于"动 ComfyUI 侧"，本项目约定不动 |
