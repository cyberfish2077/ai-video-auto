# 入口指引：三条路线怎么选、从哪开始

一句话：**只给一个主题、想全自动出片 → 快速线（B）；要剧本+分镜+六段式提示词但不想审来审去 → 快速出片（C）；
要逐层评审、三个闸门逐个批 → 导演系统（A）。**
三条路线共用同一套执行层（ComfyUI 出图/出片 + FFmpeg 合成）与同一套硬性约束。

## 0. 最省事的用法：一句话就够（用户 2026-10-15 定的约定）

| 你在对话里怎么开口 | Codex 走哪条 |
| --- | --- |
| 「我想做一个关于 <主题> 的视频，<时长>，<风格>」（**不提"导演系统"**） | **快速线，全程零确认**：Codex 把它整理成 `data\briefs\<片名>.txt`（照 `_主题模板.txt`）→ **直接全自动跑完**（剧本→参考图→出片→合成→字幕体检→交付前核对），中途不会停下来问你 → 交成片 + 质检结论 |
| 说**「快速出片」**或**「无审核」**（同义说法："不要闸门""不走评审"） | **快速出片，同样零确认**（本文件第 3 节）：Codex 把主题整理成 `projects\<片名>\brief.json` → 一条命令出四份产物（剧本/分镜/提示词包/渲染计划）+ 两个出图批次定义 → **直接接着出图出片**，中途不停下来问你（开工时会顺口告诉你预计几分钟、几张图）。无闸门、无独立评审，返修有上限 |
| 消息里出现**「导演系统」** | **导演系统**：3 道人工闸门，每道都停下来等你批准 |

**只有两种情况 Codex 会来找你**：① 主题或关键参数缺失/明显歧义（这属于"缺输入"，不是让你确认流程）；
② 出片后发现画面硬伤（例如烧进字幕、内容跑偏、某段崩形）——它会**主动重跑受影响的段**（只重跑坏的那段，
旧产物进 `_superseded\`），并在交付报告里写清哪段、为什么、重跑了什么；同一部片主动重跑最多一轮，
仍不合格就写进报告请你决定。

> 快速线**不需要你写讲稿**：DeepSeek 拿到的输入本来就叫"主题/讲稿"，一行主题它也会扩写成一个完整故事。
> 主题写得越具体越好（谁、在哪、想要什么、什么挡着他、结尾要什么味道）。
> **台词与旁白按剧本走**（2026-10-15 起不再强制零台词），声音由谁发按 `brief.json` 的 `voice_policy`：
> **对白默认让视频模型自己说**（2026-10-15 用户定案）：中文准确、口型同步；代价是画面可能带台词字幕——
> 出片后我会跑字幕体检，**只把结果统计进报告**（哪几段、哪一秒、占比），不主动返修；你说要改我再改。
> **旁白默认走 TTS**（提示词包 → `make_narration.py` → Qwen3-TTS → `mix_narration.py`）。
> 音频参考驱动口型已实测无效，不再尝试。

## 0.1 先看这张表


| 你的情况 | 走哪条 | 入口（第一个动作） | 中间要不要停 |
| --- | --- | --- | --- |
| 有讲稿（`data\briefs\*.txt`），想直接出片 | **B 快速线** | 双击项目根目录的 **`开始制作.cmd`** | 不停，一步到底 |
| 只给主题，但要先看剧本文本/分镜表/逐镜提示词，不想走三道闸门 | **C 快速出片**（触发词「快速出片」「无审核」） | 写 `projects\<片名>\brief.json`，跑 `director_system\scripts\make_film_fast.py` | **不停**（零确认、无闸门；只在缺输入或发现硬伤时找你）；`--dry-run` 可先空跑自检 |
| 只有一个想法，想先看 5 个故事方案、要审剧本/分镜/成片 | **A 导演系统** | 先写 `projects\<片名>\brief.json`，再跑 `make_ideas.py`（见下） | **停 3 次**：A 选案 / B 制作前确认 / C 成片质检 |
| 已经起了念头但忘了做到哪一步 | A | `.venv\Scripts\python.exe director_system\scripts\next_step.py` | —（它是"下一步该敲什么"的助手） |

## 1. 路线 B：全自动快速线（`开始制作.cmd`）

1. 先启动 ComfyUI（用你平时的启动器），确认 `http://127.0.0.1:8188` 能开。
2. 准备讲稿：复制 `data\briefs\示例讲稿.txt` 改成你的故事，例如 `data\briefs\我的故事.txt`。
3. 双击根目录 **`开始制作.cmd`**，按提示回答四件事（项目名 → 讲稿文件 → 时长分钟 → 风格档位）。
   命令行等价写法：`开始制作.cmd <项目名> <讲稿文件> [分钟数] [plan|yes] [风格档位]`。
4. 产物：`projects\<项目名>\final\<项目名>.mp4`、`report.md`、`script.md`、`prompts\seg-0N.txt`、`segments\`。
5. 常见坑见 `references/使用手册.md` 第六节（连不上 ComfyUI / 队列非空闲 / DeepSeek 报错…）。

> **注意**：`开始制作.cmd` **只属于路线 B**。它不做创意评审、没有闸门，也不要指望它读 `brief.json`。

## 2. 路线 A：导演系统（原创短片，3 道人工闸门）

入口在 `director_system\scripts\`，一条命令一步。**每一步做完都会停下来等你看**（闸门是真实停机点，
脚本发现上游没批准会直接拒绝运行）。

```powershell
$P = "my-short-01"      # 片名：英文或拼音，别用中文和空格

# 0) 先写创作简报 projects\$P\brief.json（题材/片长/风格/受众/情绪/限制，可照抄 nap-02 那份改）

# 1) 创意：5 个故事概念 + 独立评审 →【闸门 A 选案】
.venv\Scripts\python.exe director_system\scripts\make_ideas.py --film-id $P --brief-file projects\$P\brief.json
.venv\Scripts\python.exe director_system\scripts\next_step.py --film $P      # 忘了下一步就敲这条

# 2) 大纲 + 剧本 + 剧本评审；评审有必修项就加 --revise 返修
.venv\Scripts\python.exe director_system\scripts\make_story.py --film-id $P --concept c2

# 3) 分镜 + 分镜验证 + 评审
.venv\Scripts\python.exe director_system\scripts\make_storyboard.py --film-id $P

# 4) 提示词编译（做完自动把【闸门 B】置为"等人审"）
.venv\Scripts\python.exe director_system\scripts\make_prompts.py --film-id $P --style photoreal-cinematic

# 5) 出参考图 → 同步进 ComfyUI → 出片（先 dry-run 看要跑几个任务）
.venv\Scripts\python.exe scripts\run_batch.py dry-run --project $P
.venv\Scripts\python.exe scripts\run_batch.py run   --project $P

# 6) 合成 + 交付前核对 →【闸门 C 成片质检】
.venv\Scripts\python.exe scripts\compose_final.py --project $P --dissolve 0 --fade 0.25
.venv\Scripts\python.exe scripts\verify_final_segments.py --project $P
```

* 闸门怎么批：`review_gate.py --film-id $P --approve A|B|C --note "你的意见"`；
  看当前状态：`review_gate.py --film-id $P --show`。**批准只能由人写**，脚本只会把闸门置成"等人审"。
* 产物在哪、每节讲什么：`references/使用手册.md` **第十节**（含产物位置表、分段规则、判据）。
* 忘了下一步：`next_step.py`（上面那条），它读状态直接给你下一条命令。
* **阶段复用（2026-10-15 起）**：四个阶段各自"产物通过机械校验就复用、只补缺的那一段"——
  剧本已通过而评审失败时，重跑那条命令只重做评审（会打印 `复用已有 …`）；整段重做加 `--force`。
  另外每次请求都带**结构自查**（括号成对闭合、结尾别多写 `}`），减少"回复不是合法 JSON"的整轮作废。

## 3. 路线 C：快速出片（轻量导演通道，无闸门）

**什么时候用**：你只给一个主题，但希望拿到"能直接出片的**剧本 + 分镜 + 逐镜六段式提示词 + 渲染计划**"，
又不想走 A 的三道闸门。它**不产生**独立评审、**不设**闸门，产物全部带 `_fast` 后缀，
和严格版(A)的同名产物**互不覆盖**。

```powershell
$P = "my-fast-01"     # 片名：英文或拼音，别用中文和空格

# 0) 写创作简报 projects\$P\brief.json（最少 from_user：theme / duration_seconds / genre / style_profile）

# 1) 一条命令出四份产物（三段 DeepSeek 调用；不出图、不占显卡）
.venv\Scripts\python.exe director_system\scripts\make_film_fast.py --film-id $P --brief-file projects\$P\brief.json --style photoreal-cinematic
#    产物：screenplay_fast.json / storyboard_fast.json / prompt_pack_fast.json + prompts_fast\sN.txt
#          render_plan_fast.json / materials_definition_fast.json / boards_definition_fast.json / state_fast.json
#    先空跑自检（不调模型、不写盘）：上面那条命令末尾加 --dry-run

# 2) 出参考图（素材批先跑；多图参考批要读素材批的产物，所以排在后面）
#    批内"后一张要用同批刚出的图"（例如 剪影 要用 侧面）现在会自动处理，不用手工同步
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\materials_definition_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P-fast-materials
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\boards_definition_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P-fast-boards

# 3) 出片 → 合成 → 交付前核对 → 关掉自己拉起的 ComfyUI
#    run 会在每段提交前自动把该段的参考图补进 ComfyUI 的 input（不用再手工 sync_inputs）
.venv\Scripts\python.exe scripts\run_batch.py create --from-json projects\$P\render_plan_fast.json
.venv\Scripts\python.exe scripts\run_batch.py run    --project $P
.venv\Scripts\python.exe scripts\compose_final.py --project $P --dissolve 0 --fade 0.25
.venv\Scripts\python.exe scripts\verify_final_segments.py --project $P
.venv\Scripts\python.exe scripts\stop_comfyui.py
```

* **返修上限**：`--repairs` 默认 **2**（每段最多 3 次调用，超了报错停下，不无限重试）。
* **零确认**：和路线 B 一样，Codex 会一路跑到成片，**不会停在"等你批预算"那一步**
  （开工时说一句"预计几张图、多少分钟"只是告知）；只有缺关键输入或画面硬伤才会来找你。
* **断点续跑**：三段是串行的，**已写完且通过机械校验**的那段不重跑（省调用）；要强制重写加 `--force`，
  旧产物照例进 `history\`（只移动、不删除）。
* **自动补参考图**：`run_batch.py run` 每段提交前会把该段的参考图从素材目录补进 ComfyUI 的
  `input`（缺图会**提前**报出名字，而不是等 ComfyUI 连续拒绝提交）；要关掉加 `--no-auto-sync`。
* **资产不许白出图**：提示词包里"没有镜头用到、也没被别的资产派生引用"的资产会被机械校验拦下
  （要么用上它，要么删掉它——省一次出图）。
* **质检口径**：和 A 一样要跑 `verify_final_segments.py`；有台词/旁白时按第五节跑字幕体检
  （`check_segment_text.py`），**只检出、只报告，不主动返修**。
* 忘了参数含义：`.venv\Scripts\python.exe director_system\scripts\make_film_fast.py --help`。

## 4. 三条路都要做的收尾（别省）

| 时机 | 命令 | 为什么 |
| --- | --- | --- |
| 每天开工 | `scripts\check_env.py` + `director_system\scripts\check_director_env.py` | 环境/配置自检（应 0 错误） |
| **改过 `director_system\` 或 `src\` 之后** | `scripts\smoke_director.py` + `.venv\Scripts\python.exe -m unittest discover -s director_system/tests -t director_system/tests` | 不调模型、不花钱：脚本可导入 + 提示词可拼装 + 校验可执行 + 112 条单测（专治"一跑就崩"） |
| 出片跑完 | `scripts\stop_comfyui.py` | 只关**本次由脚本拉起**的那个 ComfyUI，释放显存；你自己开的窗口不动 |
| 交付前 | `scripts\verify_final_segments.py --project <片名>` | 核对成片里每一段是不是台账里那一段（2026-10-15 的"同名片段互相覆盖"事故就是靠它发现的） |
| 收场 | `git add -A ; git commit -m "制作：<片名>"` | 文本产物入 Git 留档（素材/分段/成片/合成音频按 `.gitignore` 不入） |

## 5. 一次制作的完整心智模型

```
路线 B：讲稿 ──────────────▶ 分段 ─▶ 出片 ─▶ 合成 ─▶ 成片

路线 C：创作简报 ─▶ 剧本 ─▶ 分镜 ─▶ 六段式提示词 ─▶ 渲染计划 ─▶ 参考图 ─▶ 出片 ─▶ 合成 ─▶ 成片（无评审、无闸门）

路线 A：创作简报 ─▶ 5 案+评审 ─【闸门A】─▶ 剧本+评审 ─▶ 分镜+评审 ─▶ 提示词+评审 ─【闸门B】─▶ 参考图 ─▶ 出片 ─▶ 合成 ─【闸门C】─▶ 成片
```

* 三条路的执行层完全一样：参考图（Qwen 出图）→ 同步进 ComfyUI 的 `input` → T8 工作流逐段出片 → FFmpeg 合成。
* 参考图/分段/成片这类大文件**只留在本地**，Git 里只有文本（剧本、分镜、提示词、台账、报告）。
* 每部片一个目录：`projects\<片名>\`；同名产物**从不覆盖**——旧的自动进 `history\` 或 `_superseded\`。
  路线 C 的产物带 `_fast` 后缀（提示词在 `prompts_fast\`），出图批次叫 `<片名>-fast-materials / -fast-boards`。

## 6. 怎么确认"自己走对了"

1. 跑完任何一条命令，最后都会打印"下一步该怎么做"；看到 `[停止]` / `[错误]` 先照它说的做，别硬冲。
2. 路线 A 的三个"确认点"：`ideas.md`（选案前）、`storyboard.md` + `prompt_pack.md`（制作前）、`final\<片名>.mp4`（交付前）。
3. 目录自检：路线 B 的片子有 `project.json`；路线 A 的片子有 `brief.json` + `state.json`（闸门留痕在里面）。
   路线 C 的片子有 `brief.json` + `state_fast.json` + `screenplay_fast.json`（**没有** `state.json`，因为它不走闸门）。
4. 读图规矩：一次对话读图 **≤10 张**且必须先降到 ≤768px（防"请求体过大导致整段对话报废"）；详见 `references/使用手册.md` 第十一/十三节。
